# Case model map

build123d enclosure for the c6remote board. Everything geometric is read from the board (`board.py` readers over `c6remote.kicad_pcb`, `export/c6remote-pos.csv`, and the STEP assembly from `scripts/export-case-refs.sh`); never hand-transcribe a board coordinate, add a reader instead. Tunables live in `params.py` only, one file, each with a rationale docstring; change values there, nowhere else. Keep `README.md` concise. It contains setup, assembly, material, input, validation, and enduring design constraints. Do not use it as a chronological design log.

`scripts/export-case-refs.sh` needs the KiCad 3D models from the private `c6remote-explode` repository. Run `scripts/link-3dmodels.sh` once for each clone or worktree.

## Commands

```bash
case/.venv/bin/python case/case.py            # build + export STLs, caps JSON, features JSON
case/.venv/bin/python case/check.py           # full validation, every check
case/.venv/bin/python case/check.py --only ir # one feature (comma list OK)
CASE_NO_CACHE=1 ...                           # bypass the solid cache both ways
CASE_CACHE_KEEP=<n> ...                       # how many solid cache keys to keep
```

### Validation delegation

For case or enclosure edits, delegate every validation command to a subagent. Do not inherit the primary model.

Select the subagent model for your client. Codex uses `gpt-6-luna`. Claude Code uses Haiku.

Delegate case builds, scoped and full checks, hardware quick and verify loops, tests, lint, renders, and documentation checks.

The main orchestrator chooses the scope and sends exact commands and known baselines.

The subagent runs the commands and reports routine results.

The main orchestrator synthesizes failures and incomplete checks.

Do not rerun passed checks in the primary agent.

Keep existing user approval rules for commands that require approval.

Both entry points are thin; the code lives in the packages. After a rebuild that changes exports, run `../c6remote-explode/preview-case.sh --full` so the viewer follows. That script builds and copies into the viewer's draft geometry set; its `--baseline` mode rebuilds the committed geometry the diff view compares against.

README case renders live in the explode viewer. From the board repo root:

```bash
../c6remote-explode/scripts/render-case-assembled.sh --blender # assembled still
../c6remote-explode/scripts/render-case-exploded.sh --blender  # exploded still
../c6remote-explode/scripts/render-case-explode-loop.sh        # looping explode turntable (WebP)
```

All three render with Blender's Cycles.

Presets sit in `~/dev/c6remote-explode/presets/`. Pose a shot in the viewer, press Copy preset JSON, and overwrite the preset to lock the camera.

## Layout

- `params.py` tunables with rationale. `board.py` board readers (`wheel_profile`, `part_envelope`, `usb_envelope`, `usb_profile`, `keepouts`). STEP occurrence names assign solids to their component references, so nearby parts do not claim the XIAO body. `cache.py` disk cache: BREP blobs plus cached STLs in `case/.cache/`, keyed on a sha256 over every geometry input including the board files; prints a hit or miss line every run. It keeps the keys that recent runs used, `CACHE_KEEP` of them, so a parameter that you try and then revert replays from disk instead of a rebuild. The verdicts sit under the key, so they come back with the solids. Set `CASE_CACHE_KEEP` to change the count, or to 1 to keep only the live key.
- `model/stack.py` the z-stack, single source: `BOARD_TOP`, `CAVITY_FRONT`, `SHELL_FRONT`, `COUNTERBORE_TOP`, `CAVITY_BACK`, `SHELL_BACK`, wheel constants read from the board. Everything imports it; nothing imports the entry points. The recessed front's face is one superellipse of `FACE_POWER` across x, from side wall to side wall. It falls `FACE_SIDE_DROP` from its crown, `SHELL_FRONT`, to `FACE_WALL_TOP`. Over `FACE_END_ROLL` it rolls into each end wall with the same power. Its half width at each y is the plan's own (`_span`), so it meets every wall vertically at `FACE_WALL_TOP`, corners included. `face_z(x, y)` is the formula, and every face-height consumer reads it. Use `SHELL_FRONT` only as a bound. `face_body()` is the shell body: one cubic B-spline face in patches of `FACE_PATCH_SPANS` knot spans, walls extruded from the face's own boundary edges, and a flat floor, sewn into one solid. The patches keep the booleans fast, because each tool face is tested only against the patches it overlaps. Each pole of the face is a pole of the fitted unit section (`_face_section`) scaled by a pole of the fitted stations along y (`_face_stations`). The stations use arc length on the crown and a double knot where each corner arc meets a side wall. The build raises if the fit strays past `FACE_FIT_TOLERANCE` from `face_z()`. `_bspline_patches()` is the one raw OCP helper, because build123d makes no surface from poles and knots. A single face over the whole top reports a wrong `.volume`, and patches also fix that. Each patch is its own segment of the surface, because the `clean()` after each boolean merges faces that share one surface. The exported STL, not the fit, sets `FACE_SECTION_SPANS`: the mesher places its nodes from the knots, and with too few spans the STL sags below the face near the crown although it is exported at a 0.01 tolerance. After a change to the face's knots or patches, measure that sag on the exported STL. The face is a spline and not an analytic surface, because a planar facet almost parallel to an analytic cylinder's axis makes a cut fail without an error. `cap_top(ref)` and `stem_top(ref)` follow the face per key.
- `model/shape.py` shared primitives (`_fuse`, `_cut`, `_isect`, `_slab`, `_hole`, `_rounded_prism`). Touching solids must merge; a cut across a compound fails.
- `model/backform.py` back outer surface: `contour_depth`, `end_depth`, tip roll, the loft. Its sections are the plan profile's own chord, so the bottom round lands tangent to the wall around the plan corners and not on the straight sides alone. `model/cell.py` pouch bay (split from hardware to break an import cycle; keep it below both). `model/hardware.py` the end-wall closure screw and the block it threads into. It is the only screw in the case. `end_screw()` is the screw itself, placed off the counterbore floor and `end_screw_length()`. It exports as `c6remote-case-screw.stl`, a reference part that nobody prints. Keep it out of the printability checks. `model/shells.py` front and back shells, skirt, lap, the seam shadow groove round the back lap's outer top edge (`seam_shadow()`), catches. `front_shell(fdm=True)` is the same shell with the outline groove cut in place of the recess and `front_edge_round(fdm)` giving the end roll length on the recessed front and the 45 degree chamfer leg on the FDM front, exported as `c6remote-case-front-fdm.stl`: identical under the face, so one cap, pad and back fit either. The recess cannot print face down and face down is the only orientation that keeps support off the cosmetic face. Its face also sits `FDM_FACE_DROP` lower (`front_face`, `stack.py`), so flattening the dish does not keep the material the dish removed, and `checks/fdm.py` holds the ceilings that drop thins. `model/features.py` keys it under `c6remote-case-front-fdm.stl`, with the front's entries but for the groove in place of the recess. `model/keypad.py` the front face's one merged recess: three superellipse basins on a single centreline joined by two Hermite bridges into one C1 depth field (`keypad_recesses`, `keypad_necks`, `recess_spine`, `face_depth_at`, measured down from `face_z()` so the rim outline does not move with the face, and `face_floor_at` the built surface. Each basin is a `Recess` with its own exponent, axis rounding, soft rim and lip lift. `recess_spine(y)` returns a `Spine`, the eight scalars one cross-section needs: inside a basin they are that basin's own, and inside a neck each is one Hermite cubic whose end values and slopes `keypad_necks()` computes once. `_cross()` is the one section formula, `_level()` of the point against `_level()` of the rim. Across each neck the depth follows `_neck_floor()` instead: flat from the key row nearest the wheel (`KEY_ROW_FLATTEN`), then a cube that meets the wheel basin's own profile inside the bore, so the floor never rises between two basins and the outline does not change. `_soft_rim` can roll each basin's last few tenths of depth into the face (the `soft` field, set by `WHEEL_RIM_SOFT`, `KEYPAD_RIM_SOFT` and `KEYPAD_RIM_SOFT_2`). All three are zero, because the rim chamfer replaces the roll. In the two key basins, `KEYPAD_LIP_LIFT` and `KEYPAD_LIP_CREST` lift the floor to a crest before the rim, and the rim does not move (`_spine_depth`). Join roundness is `KEYPAD_JOIN_REACH`, per basin, and `neck_radius` measures what it buys; the wheel basin carries its own lower `WHEEL_SQUIRCLE_N` and full axis rounding so its flanks read round) and cut as one loft along y (`keypad_recess`). A rim chamfer, `RECESS_CHAMFER_W` wide, runs round the inside of the rim on the recessed front only, and `face_depth_at()` includes it. In each section normal to the outline, `_rim_section()` is a round that leaves the face `RECESS_CHAMFER_ROUND_OUT` outside the outline with the face's slope and runs `RECESS_CHAMFER_ROUND_W` inside it, any straight section, and a round `RECESS_CHAMFER_INNER_ROUND_W` wide that meets the dish floor with the floor's slope. `keypad_recess_cut()` keeps the loft inside the chamfer's inner ring and fuses it with the chamfer cutter `keypad_chamfer()`, so the outline does not move. The cutter must not share a face, edge or vertex with the clip wall on that ring, or the fuse or the shell cut fails without an error. So its floor crosses the clip wall `CHAMFER_SEAM_LIFT` above the dish, on points staggered from the ring's points, and then rises clear of the dish. `face_depth_at()` is zero only outside the round's start ring, so face-height consumers such as `ring_land_left()` see that cut. Each section's first round ring sits `CHAMFER_ROUND_GAP` under the face, because a ring of points at the face also makes the cut fail without an error. After a change here, compare the front's volume with the shell before the recess cut, because a skipped cut returns a valid shell. `recess_stations` starts from the superellipse-parameter stations and halves every span whose ruled patches would crease or twist more than `FACET_ANGLE`, and every station uses the same `_profile_u()` points, placed by arc length and turning, so the rims show no facets; the same field's plan outline as a face (`recess_outline`) and as the shallow slot the FDM front's flat face carries instead of the recess (`keypad_outline_groove`, a true 2D offset either side of that outline; the outline is the rim itself, unclamped, so the line is the same on both fronts. The rim runs where the recessed face already turns down toward the side walls, so the FDM front uses a small chamfer instead: `EDGE_R_FRONT_FDM` is the chamfer leg, inside the bound `KEYPAD_EDGE_MARGIN` less half a groove width less `FDM_OUTLINE_EDGE_CLEAR`. `FDM_OUTLINE_EDGE_CLEAR` is load-bearing: at zero the groove's outer edge goes coincident with the chamfer's inner edge, and the exported STL comes back torn along the face while every other reading stays green); plus the pad's two lobes and stems, one lobe per `_pad_lobe` call. Each lobe is the box of its own switch centres grown by `pad_reach()`, half the fused TPU and FDM keytop plus `PAD_MARGIN` (`pad_lobe_box`). The old outline grew off the cap footprint and stood inside the ring insert's D6 and D7 lobes. The rigid cap flange overhangs the web on the outer side of each outer key, and the press goes through the stem. The moulded lobes also carry `pad_skirt`, a perimeter wall dropping `PAD_SKIRT_DEPTH` below the web, which `pad_skirt_breaks` opens over any board part still in its way. The STEP has no switch bodies, because the export drops the VRML model, so `switch_bodies()` adds a `SWITCH_BODY` box for each switch to the obstacles and to the skirt checks. On the V3 board nothing breaks the wall: the depth clears C3, R1 and R12, and the outline clears C1 and the switch bodies in plan. The mic notch is cut only where `pad_mic_notch()` says the clearance circle reaches the lobe, which it does not at the present outline. The lobes stop short of the side walls, so `pad_tabs()` puts a web-only locating tab on each long side of each lobe, at its mid-length, out to the `PAD_FIT` line of `_pad_limit()`. `pad_lobe_face()` adds them after the clip, because a clip edge on a face edge leaves a sliver. `pad_lobe_face(tabs=False)` is the outline the skirt and the skirt walk follow. `checks/keypad.py` `pad_x_float()` holds the float in x to `SOCKET_LEAD` on every pad variant, and `pad_wall_fit()` holds `PAD_FIT` at the tabs. `button_pad(fdm=True, skirt=True, grooves=False)` is the FDM pad with the same skirt but a plain grid web, with no grooves and no chamfer, exported as `c6remote-case-pad-tpu.stl`, a one-piece TPU pad that pairs with the recessed front. The moulded pad and the TPU pad have a plain web without isolation grooves, so only the FDM pad has grooves, and `grooves` applies only when `fdm` is true. `legacy_top_pad` is the FDM pad's SW1/SW2 lobe for a V2 board, exported as `c6remote-case-pad-fdm-v2-top.stl`. It keeps the V3 plungers and adds one nib at each V2 switch. Each nib engages `LEGACY_SWITCH_TOP` by `LEGACY_NIB_EXTENSION`. The kept V3 plungers engage `SWITCH_TOP` by the same extension. Its keytops stand level with the other keys in their column, at `cap_top(ref)`. `legacy_top_pad` has its own outline, `pad_lobe_box(v2=True)`: the V3 box grown to reach each V2 nib by `PLUNGER_D` plus `PAD_MARGIN`, which stops short of the D6 lobe, so it takes no notch. `legacy_top_pad(skirt=True)` adds a skirt that ends at `PAD_SKIRT_BOTTOM`, so both lobes' skirts end level, broken over the V3 part bodies that `board.legacy_part_solids()` moves to their V2 placements and over the V2 SW1 and SW2 bodies under its wheel-side edge, exported as `c6remote-case-pad-tpu-v2-top.stl`, which also pairs with the recessed front. `button_pad(..., legend=False)` and `button_pad(..., legend=False, v2=True)` are the two blank TPU exports, the second a complete V2 pad in one STL. `legacy_top_pad(fdm=False, skirt=True)` is the moulded pad's V2 lobe for the standard caps, exported as `c6remote-case-pad-v2-top.stl`. `model/caps.py` keycap chain (`cap_body` through `cap_counterbore`), all four widths the same superellipse via `_key_prism`, on the caps' own `KEY_SQUIRCLE_N` rather than the recesses' `KEYPAD_SQUIRCLE_N` so their flanks bow out further, plus `cap_flat` for what a legend can occupy (it tracks that exponent, so lowering it tightens the legend ink pass). `cap_face_hole_lead_in` gives the triangles of the face-hole lead-in cutter. `front_shell()` cuts them, and `counterbore_land()` reads the land ring's mid-line on all four sides off the same triangles. `model/legends.py` legends as stroked outlines of font glyphs and thickened centerlines of SVG glyphs, `LEGEND_STROKE_W` wide and `LEGEND_DEPTH` deep (fonts in `case/fonts/`, glyphs in `case/glyphs/`). `model/wheel_ring.py` the clearance band the pad's lobes stay out of around the wheel (`pad_clear_terms()`: the lip, the LEDs, and the ring insert's lobes plus `PAD_SKIRT_CLEARANCE`, which governs; the moulded ring is gone, and so is the cut that used to sever the pad), the shell's close-fit wheel opening (the crown stands `FACE_CROWN_OVER_WHEEL` above the wheel's own measured top, and the wheel dish takes the seat below the knob top), and the LED ring, which carries the six LEDs' light around the wheel. The recessed front keeps no shell over that ring: a roof thin enough to pass light reads under the SLS minimum and no parameter reaches it, so `led_ring_channel()` bores one circle at `led_ring_face_r()` from the cavity ceiling clear through the face and `led_ring_insert()` fills it, exported as `c6remote-ring-insert.stl` and printed in natural PA12 while the shell takes the dye. `led_ring_face_r()` is `RING_LIFT_CLEAR` inside the cavity wall where that wall comes closest, and the same circle holds on every bearing, so the opening in the face is round and the part clears the wall as it rises straight up. The band stops short of the LEDs, so `led_ring_lobes()` hangs one lobe on the insert over each: a dome whose rim sits `RING_LOBE_WRAP` under that LED's top face, a `RING_LOBE_WALL` wall outside the rim, and a 45 degree flare back up into the shell. `led_ring_lobe_rim_r()` solves the rim radius that leaves `RING_LOBE_GAP` over the LED's outer corner rather than taking it off a radial clearance, and `RING_LOBE_STRAIGHT` sets how straight the dome runs between its ends, because the flare over it is a plane at 45 and the wall between them is the vertical gap times cos(45). `led_ring_lobe_roof()` measures that wall normal to the flare and to the `RING_LOBE_SHOULDER` chamfer on each lobe's top outer corner (`led_ring_lobe_lid()`), which is what checks/fab.py reads. The chamfer keeps a pressed SW6 flange off the D7 lobe, and `checks/wheel_ring.py` `pressed_caps_clear_lobes()` holds that gap. Each dome is open on its inner side, because a wall there would stand between the LED and the ENC1 lip and `LIP_CLEAR_R` leaves no room; the band sits over that half of the package anyway. The flare is both the light path and the retention: `led_ring_lobe_pockets()` opens a wedge in the shell for each one and the shell keeps `LED_RING_FACE_ROOF` of land over it, which `keypad.ring_land_left()` walks. The lobes are local to the six LEDs, because a flare all the way round would reach past the cavity wall near the X axis and the insert could not lift past it. It is bonded like the IR window, because nothing stands under it, and `led_ring_feet()` adds six feet that catch it if that bond fails, one midway through each gap between the LEDs, clearing the board by `RING_FOOT_GAP` rather than resting on it. Each is a sector of the band it hangs off: an arc just inside the band's facets outward (`FOOT_CHORD_INSET`), so no corner stands past the round outline, and `LIP_CLEAR_R` inward, which is the rotating envelope and not the band's own inner edge, so all six are the same. The channel's arch, its inner bevel and its raked mouth survive only on the FDM front, which keeps its own roof and web. The checks moved with the material: `checks/wheel_ring.py` walks the insert as a solid where it used to walk the channel as a void, wants the shell empty over the whole band, and reads the insert's outer face on every bearing to prove the ring came out round. `model/ir.py` U2's rounded -Z back-floor aperture and conformal stepped inside-fit insert, plus D1's unchanged +Y emitter bore. `model/mic.py` funnel inlet: a cone that widens up from the board port into a concave fillet band at the mouth. On the recessed front the band follows the dish floor (`mic_band_point`), and its top ring is `MIC_MOUTH_LIFT` above the floor. As a result, the floor cuts the band in one edge at `mic_floor_edge_r()` all the way round. The band is a lofted shell, sewn to a ruled chimney up to the face. A solid loft cannot cap a top ring that is not flat. `mic_bore(fdm=True)` keeps the flat torus fillet and ends the funnel at `FDM_FACE`, so the FDM front does not move with the recessed face. `model/usb.py` cuts the end-wall slot around the underside XIAO USB connector. `model/qwiic.py` defines the side-wall `qwiic_slot()`, its flush breakaway cover with two side bridges, and the internal `battery_plug_envelope()` routing corridor. The connector openings use the measured board bodies and their clearance parameters. The battery corridor is an allowance, not a measured plug model. `model/features.py` the names behind the meshes: one table from each exported STL to the builders that add to or cut that part, each with its source, the parameters that source reads, whether it is material or void, and its bounding box in the case frame. It names the support keepouts as well as the runs: each break between two runs is exported as a `clear` box called after the obstacle that opens it, so a click on the bare wall in a break still resolves to an id. `model/cli.py` `main()`: export set and summary. The `export/c6remote-caps.json` and `export/c6remote-features.json` exports feed the viewer; never remove them. Each cap also exports a `-blank` twin at `legend=False`, which stays out of `c6remote-caps.json` because the viewer loads every entry there as a cap.
- `model/support.py` makes the board support runs from the board profile, bottom courtyards, assembly solids, the end screw block, and support parameters. `support_obstacles()` names each keepout after the board: a courtyard refdes, a through-board solid index, or `end screw block`. `ledge_breaks()` and `_ledge_blank()` are shared with the front ledges. Both the support checks and the feature export read the names.
- `model/front_ledge.py` makes the front shell's board hold-down ledges: the back ledge blank turned over, with flat undersides at `BOARD_TOP + FRONT_LEDGE_GAP`, one run set per long side, inside `FRONT_LEDGE_REACH` of the grip edge. `front_ledge_obstacles()` derives every break from the top courtyards, the assembly solids above the bearing plane, and the V2 part bodies. `front_shell()` fuses `front_ledge_runs()` into both fronts.
- `checks/support.py` probes clearance, bearing, minimum run length, print angle, and back-shell fusion on the built geometry.
- `checks/front_ledge.py` probes the built front shell: run window and length, fusion, bearing plane and flat width, clearance to courtyards and solids, material intact after the later cuts, slope angle, and fit against the pads and caps.
- `checks/legacy.py` probes the V2 top pad: the nib and kept V3 plunger bottoms and the fit in the FDM front. It probes the V2 TPU top pad's skirt depth against `PAD_SKIRT_BOTTOM`, and its board clearance, and that each moved V2 body sits at its V2 placement. `board.legacy_frame_check()` reads the V2 outline out of `board/c6remote-v2-board-only.step`, static geometry frozen at release `2026.8.0`, commit `d0a2c2e`, and fails if V2 and V3 stop sharing a frame. `board.legacy_components()` reads V2's placements out of `board/c6remote-v2-pos.csv`, frozen at the same commit. Do not regenerate either file. V2 shell fit is not verified. Read `README.md` for the compatibility limits.
- `checks/fdm.py` probes the FDM front: the face is material at every site `checks/keypad.py` reads the recess as dished at, the groove is cut to depth all the way round with real material left under it, and the flat the built shell has out to its own top edge chamfer is `EDGE_R_FRONT_FDM`'s with `FDM_OUTLINE_EDGE_CLEAR` of it outboard of the groove. It imports `checks/keypad.py`'s own probe sites so the two passes read the same places with opposite verdicts.
- `checks/fab.py` measures the wall thickness of every STL that PCBWay prints by inward rays against `FAB_MIN_WALL[FAB_PROCESS]`, PCBWay's published minimum. `PARTS` is that list: the two shells and the ring insert. `ACCEPTED` is the baseline of the features that are thin today, each with a floor on its sheet reading and a cap on its thin area.
- `checks/` mirrors the features, one module each, `checks/cli.py` owns the registry, solid demand-loading, and `--only`. Cross-feature checks (`interference`, `feature_clashes`) live in the `assembly` feature; a scoped run prints which features it skipped and exits nonzero on failure. `checks/verdicts.py` keeps the verdict of each pass on disk. Its key is the solid cache key with a hash of every file under `checks/`, plus `check.py` and `case.py`. If neither key moves, the run replays the stored verdicts and builds no solid. A pass that raised an exception is never stored, because the cause is as often the environment as the geometry. To run every pass again with the solids still warm, use `--recheck`. `checks/common.py` reads a ray as a curve-surface intersection against the real faces. It does not boolean the segment against the solid. The boolean it replaced read some pad lobes 0.26 mm short, against both the faces and the tessellation. Do not put the boolean back.

## Board support ledges

Keep the support ledges in the back shell. Use the same full-length runs to cut matching relief from the front shell. The front shell also has hold-down ledges near the grip end (`model/front_ledge.py`). They mirror the back ledges from above and reuse the same blank, break rules, and parameters. The relief stands `SUPPORT_SKIRT_FIT` above the ledge tops, so the front skirt never lands on a ledge.

Keep a 0.25 mm gap below the board and a 3 mm bearing surface. Keep one straight 45 degree underside for FDM printing.

Derive all breaks from board obstacles. Remove fragments below `SUPPORT_MIN_RUN`. A through-board solid that reaches a long side wall opens a break of at least `SUPPORT_MIN_BREAK`. Do not add local end trims or separate wedges.

After a support change, run this workflow from the repository root:

```bash
case/.venv/bin/python case/check.py --only support,front_ledge,shells
case/.venv/bin/python case/check.py
../c6remote-explode/preview-case.sh --full
```

Inspect both shell STLs and the exploded view. Confirm that the front shell has no unwanted lower side geometry.

## Disciplines

- A check must probe the BUILT solid, not restate the formula that built it. This model shipped several vacuous passes before that rule; assume any new check is vacuous until proven otherwise.
- The solid is not the artifact either: STLs are, and a valid solid can still mesh to a torn surface. `parts_are_sound` in `checks/shells.py` and `checks/fab.py` are the passes that read a mesh. `parts_are_sound` exists because a keypad recess once lofted to something BRepCheck called valid whose STL was ripped open across the whole front face, with every other pass green. After any change to a lofted or swept surface, look at the exported STL, not just the check output.
- Geometry stays on build123d's public API. No `import OCP`, no `.wrapped`: build123d already covers booleans, `.volume`, STEP/BREP IO, and STL tessellation (`export_stl`). If an operation is genuinely mesh-native (mesh boolean, point sampling, repair), `trimesh` is in `requirements.txt`, and `checks/fab.py` uses it. Raw OCP through `.wrapped` is the last resort, confined to one small helper with a comment saying what build123d lacks.
- Perturb-test every new check: break the param, watch it fail with a sensible message, restore.
- Refactors gate on byte-identical exports (md5 over `case/export/`) and identical check output. STL export is deterministic enough to gate on, except one known flake in the back shell tessellation that the STL cache absorbs.
- A green scoped run is not a green full run; the skip line exists so nobody mistakes one.
- `SWITCH_HEIGHT` and `SWITCH_TRAVEL` are hand-entered, unmeasured; measure a real TL3315 before printing.
