# Case model map

build123d enclosure for the c6remote board. Everything geometric is read from the board (`board.py` readers over `c6remote.kicad_pcb`, `export/c6remote-pos.csv`, and the STEP assembly from `scripts/export-case-refs.sh`); never hand-transcribe a board coordinate, add a reader instead. Tunables live in `params.py` only, one file, each with a rationale docstring; change values there, nowhere else. Keep `README.md` concise. It contains setup, assembly, material, input, validation, and enduring design constraints. Do not use it as a chronological design log.

## Commands

```bash
case/.venv/bin/python case/case.py            # build + export STLs, caps JSON, features JSON
case/.venv/bin/python case/check.py           # full validation, every check
case/.venv/bin/python case/check.py --only ir # one feature (comma list OK)
CASE_NO_CACHE=1 ...                           # bypass the solid cache both ways
```

### Validation delegation

For case or enclosure edits, delegate every validation command to a subagent with the explicit model `gpt-5.6-luna`.

Select `gpt-5.6-luna` explicitly. Do not inherit the primary model.

Delegate case builds, scoped and full checks, hardware quick and verify loops, tests, lint, renders, and documentation checks.

The main orchestrator chooses the scope and sends exact commands and known baselines.

The Luna subagent runs commands and reports routine results.

The main orchestrator synthesizes failures and incomplete checks.

Do not rerun passed checks in the primary agent.

Keep existing user approval rules for commands that require approval.

Both entry points are thin; the code lives in the packages. After a rebuild that changes exports, run `../c6remote-explode/preview-case.sh --full` so the viewer follows. That script builds and copies into the viewer's draft geometry set; its `--baseline` mode rebuilds the committed geometry the diff view compares against.

README case renders live in the explode viewer. From the board repo root:

```bash
../c6remote-explode/scripts/render-case-assembled.sh --blender # assembled still
../c6remote-explode/scripts/render-case-exploded.sh --blender  # exploded still
../c6remote-explode/scripts/render-case-explode-loop.sh        # looping explode turntable (WebP)
```

All three render with Blender's Cycles; add `--rig` to render on the Windows Rig.

Presets sit in `~/dev/c6remote-explode/presets/`. Pose a shot in the viewer, press Copy preset JSON, and overwrite the preset to lock the camera.

## Layout

- `params.py` tunables with rationale. `board.py` board readers (`wheel_profile`, `part_envelope`, `usb_envelope`, `usb_profile`, `keepouts`). STEP occurrence names assign solids to their component references, so nearby parts do not claim the XIAO body. `cache.py` disk cache: BREP blobs plus cached STLs in `case/.cache/`, keyed on a sha256 over every geometry input including the board files; prints a hit or miss line every run.
- `model/stack.py` the z-stack, single source: `BOARD_TOP`, `CAVITY_FRONT`, `SHELL_FRONT`, `COUNTERBORE_TOP`, `CAVITY_BACK`, `SHELL_BACK`, wheel constants read from the board. Everything imports it; nothing imports the entry points. The recessed front's face is one superellipse of `FACE_POWER` across x, from side wall to side wall. It falls `FACE_SIDE_DROP` from its crown, `SHELL_FRONT`, to `FACE_WALL_TOP`. Over `FACE_END_ROLL` it rolls into each end wall with the same power. Its half width at each y is the plan's own (`_span`), so it meets every wall vertically at `FACE_WALL_TOP`, corners included. `face_z(x, y)` is the formula, and every face-height consumer reads it. Use `SHELL_FRONT` only as a bound. `face_body()` is the shell body: one cubic B-spline face in patches of `FACE_PATCH_SPANS` knot spans, walls extruded from the face's own boundary edges, and a flat floor, sewn into one solid. The patches keep the booleans fast, because each tool face is tested only against the patches it overlaps. Each pole of the face is a pole of the fitted unit section (`_face_section`) scaled by a pole of the fitted stations along y (`_face_stations`). The stations use arc length on the crown and a double knot where each corner arc meets a side wall. The build raises if the fit strays past `FACE_FIT_TOLERANCE` from `face_z()`. `_bspline_patches()` is the one raw OCP helper, because build123d makes no surface from poles and knots. A single face over the whole top reports a wrong `.volume`, and patches also fix that. Each patch is its own segment of the surface, because the `clean()` after each boolean merges faces that share one surface. The exported STL, not the fit, sets `FACE_SECTION_SPANS`: the mesher places its nodes from the knots, and with too few spans the STL sags below the face near the crown although it is exported at a 0.01 tolerance. After a change to the face's knots or patches, measure that sag on the exported STL. The LED channel ceiling is `LED_RING_FACE_ROOF` under the built face, or the arch `arch_z(x, LED_RING_TOP, LED_RING_SAG)` where the arch is higher, so the channel is never shallower than the arch makes it. `arch_block()` no longer cuts the channel. Its arc is an exact rational spline, not an analytic circle, because a planar facet almost parallel to an analytic cylinder's axis makes a cut fail without an error. The face is a spline for the same reason. `cap_top(ref)` and `stem_top(ref)` follow the face per key.
- `model/shape.py` shared primitives (`_fuse`, `_cut`, `_isect`, `_slab`, `_hole`, `_rounded_prism`). Touching solids must merge; a cut across a compound fails.
- `model/backform.py` back outer surface: `contour_depth`, `end_depth`, tip roll, the loft. Its sections are the plan profile's own chord, so the bottom round lands tangent to the wall around the plan corners and not on the straight sides alone. `model/cell.py` pouch bay (split from hardware to break an import cycle; keep it below both). `model/hardware.py` the end-wall closure screw and the block it threads into. It is the only screw in the case. `model/shells.py` front and back shells, skirt, lap, catches. `front_shell(fdm=True)` is the same shell with the outline groove cut in place of the recess and `front_edge_round(fdm)` giving the end roll length on the recessed front and the 45 degree chamfer leg on the FDM front, exported as `c6remote-case-front-fdm.stl`: identical under the face, so one cap, pad and back fit either. The recess cannot print face down and face down is the only orientation that keeps support off the cosmetic face. Its face also sits `FDM_FACE_DROP` lower (`front_face`, `stack.py`), so flattening the dish does not keep the material the dish removed, and `checks/fdm.py` holds the ceilings that drop thins. `model/features.py` keys it under `c6remote-case-front-fdm.stl`, with the front's entries but for the groove in place of the recess. `model/keypad.py` the front face's one merged recess: three superellipse basins on a single centreline joined by two Hermite bridges into one C1 depth field (`keypad_recesses`, `keypad_necks`, `recess_spine`, `face_depth_at`, measured down from `face_z()` so the rim outline does not move with the face, and `face_floor_at` the built surface. Each basin is a `Recess` with its own exponent, axis rounding, soft rim and lip lift. `recess_spine(y)` returns a `Spine`, the eight scalars one cross-section needs: inside a basin they are that basin's own, and inside a neck each is one Hermite cubic whose end values and slopes `keypad_necks()` computes once. `_cross()` is the one section formula, `_level()` of the point against `_level()` of the rim. Across each neck the depth follows `_neck_floor()` instead: flat from the key row nearest the wheel (`KEY_ROW_FLATTEN`), then a cube that meets the wheel basin's own profile inside the bore, so the floor never rises between two basins and the outline does not change. `_soft_rim` can roll each basin's last few tenths of depth into the face (the `soft` field, set by `WHEEL_RIM_SOFT`, `KEYPAD_RIM_SOFT` and `KEYPAD_RIM_SOFT_2`). All three are zero, because the rim chamfer replaces the roll. In the two key basins, `KEYPAD_LIP_LIFT` and `KEYPAD_LIP_CREST` lift the floor to a crest before the rim, and the rim does not move (`_spine_depth`). Join roundness is `KEYPAD_JOIN_REACH`, per basin, and `neck_radius` measures what it buys; the wheel basin carries its own lower `WHEEL_SQUIRCLE_N` and full axis rounding so its flanks read round) and cut as one loft along y (`keypad_recess`). A rim chamfer, `RECESS_CHAMFER_W` wide, runs round the inside of the rim on the recessed front only, and `face_depth_at()` includes it. In each section normal to the outline, `_rim_section()` is a round that leaves the face `RECESS_CHAMFER_ROUND_OUT` outside the outline with the face's slope and runs `RECESS_CHAMFER_ROUND_W` inside it, any straight section, and a round `RECESS_CHAMFER_INNER_ROUND_W` wide that meets the dish floor with the floor's slope. `keypad_recess_cut()` keeps the loft inside the chamfer's inner ring and fuses it with the chamfer cutter `keypad_chamfer()`, so the outline does not move. The cutter must not share a face, edge or vertex with the clip wall on that ring, or the fuse or the shell cut fails without an error. So its floor crosses the clip wall `CHAMFER_SEAM_LIFT` above the dish, on points staggered from the ring's points, and then rises clear of the dish. `face_depth_at()` is zero only outside the round's start ring, so face-height consumers such as `ring_roof_left()` see that cut. Each section's first round ring sits `CHAMFER_ROUND_GAP` under the face, because a ring of points at the face also makes the cut fail without an error. After a change here, compare the front's volume with the shell before the recess cut, because a skipped cut returns a valid shell. `recess_stations` starts from the superellipse-parameter stations and halves every span whose ruled patches would crease or twist more than `FACET_ANGLE`, and every station uses the same `_profile_u()` points, placed by arc length and turning, so the rims show no facets; the same field's plan outline as a face (`recess_outline`) and as the shallow slot the FDM front's flat face carries instead of the recess (`keypad_outline_groove`, a true 2D offset either side of that outline; the outline is the rim itself, unclamped, so the line is the same on both fronts. The rim runs where the recessed face already turns down toward the side walls, so the FDM front uses a small chamfer instead: `EDGE_R_FRONT_FDM` is the chamfer leg, inside the bound `KEYPAD_EDGE_MARGIN` less half a groove width less `FDM_OUTLINE_EDGE_CLEAR`. `FDM_OUTLINE_EDGE_CLEAR` is load-bearing: at zero the groove's outer edge goes coincident with the chamfer's inner edge, and the exported STL comes back torn along the face while every other reading stays green); plus the pad's two lobes and stems, one lobe per `_pad_lobe` call. The moulded lobes also carry `pad_skirt`, a perimeter wall level with the plunger contacts, which `pad_skirt_breaks` opens over board parts. `button_pad(fdm=True, skirt=True, grooves=False)` is the FDM pad with the same skirt but a plain grid web, with no grooves and no chamfer, exported as `c6remote-case-pad-tpu.stl`, a one-piece TPU pad that pairs with the recessed front. The moulded pad and the TPU pad have a plain web without isolation grooves, so only the FDM pad has grooves, and `grooves` applies only when `fdm` is true. `legacy_top_pad` is the FDM pad's SW1/SW2 lobe for a V2 board, exported as `c6remote-case-pad-fdm-v2-top.stl`. It keeps the V3 plungers and adds one nib at each V2 switch. Each nib engages `LEGACY_SWITCH_TOP` by `LEGACY_NIB_EXTENSION`. The kept V3 plungers engage `SWITCH_TOP` by the same extension. Its keytops stand level with the other keys in their column, at `cap_top(ref)`. `legacy_top_pad(skirt=True)` adds a skirt that ends at the V3 pad's `PAD_SKIRT_BOTTOM`, so both lobes' skirts end level, broken over the V3 part bodies that `board.legacy_part_solids()` moves to their V2 placements, exported as `c6remote-case-pad-tpu-v2-top.stl`, which also pairs with the recessed front. `button_pad(..., legend=False)` and `button_pad(..., legend=False, v2=True)` are the two blank TPU exports, the second a complete V2 pad in one STL. `legacy_top_pad(fdm=False, skirt=True)` is the moulded pad's V2 lobe for the standard caps, exported as `c6remote-case-pad-v2-top.stl`. `model/caps.py` keycap chain (`cap_body` through `cap_counterbore`), all four widths the same superellipse via `_key_prism`, on the caps' own `KEY_SQUIRCLE_N` rather than the recesses' `KEYPAD_SQUIRCLE_N` so their flanks bow out further, plus `cap_flat` for what a legend can occupy (it tracks that exponent, so lowering it tightens the legend ink pass). `cap_face_hole_lead_in` gives the triangles of the face-hole lead-in cutter. `front_shell()` cuts them, and `counterbore_land()` reads the land ring's mid-line on all four sides off the same triangles. `model/legends.py` legends as stroked outlines of font glyphs and thickened centerlines of SVG glyphs, `LEGEND_STROKE_W` wide and `LEGEND_DEPTH` deep (fonts in `case/fonts/`, glyphs in `case/glyphs/`). `model/wheel_ring.py` the clearance band the pad's lobes stay out of around the wheel (uncovering the LEDs; the moulded ring is gone, and so is the cut that used to sever the pad), the shell's close-fit wheel opening (the crown stands `FACE_CROWN_OVER_WHEEL` above the wheel's own measured top, and the wheel dish takes the seat below the knob top), and the LED ring channel, an annular void in the ceiling that carries the six LEDs' light around the wheel under a translucent roof. On the recessed front the channel ceiling is `led_ring_ceiling_under()`: `LED_RING_FACE_ROOF` under the built face, or the arch where that is higher (`led_ring_ceiling_at`, `LED_RING_SAG` lower at each side wall). That ceiling is not a surface of revolution, so `led_ring_channel()` is a ruled loft through one section at each of `LED_RING_STATIONS` bearings, closed on itself. In each section the outer wall is plumb at the mouth up to `led_ring_rake_foot()`, then rakes in at 45 degrees up to the ceiling at `led_ring_flat_outer_r()`, where a 45 degree line from the mouth meets the arch. A raised ceiling lifts the rake and does not narrow the roof flat. The inner bevel hangs the full `LED_RING_INNER_CHAMFER` from the local ceiling (`led_ring_bevel_top`). The face falls to the arch at the east and west sides and thins the roof there, and `ring_roof_left` counts it. `model/ir.py` U2's rounded -Z back-floor aperture and conformal stepped inside-fit insert, plus D1's unchanged +Y emitter bore. `model/mic.py` funnel inlet, tapering cone up from the board port into a tangent fillet at the mouth. `mic_bore(fdm=True)` ends the funnel at `FDM_FACE`, so the FDM front does not move with the recessed face. `model/usb.py` cuts the end-wall slot around the underside XIAO USB connector. `model/qwiic.py` defines the side-wall `qwiic_slot()`, its flush breakaway cover with two side bridges, and the internal `battery_plug_envelope()` routing corridor. The connector openings use the measured board bodies and their clearance parameters. The battery corridor is an allowance, not a measured plug model. `model/features.py` the names behind the meshes: one table from each exported STL to the builders that add to or cut that part, each with its source, the parameters that source reads, whether it is material or void, and its bounding box in the case frame. It names the support keepouts as well as the runs: each break between two runs is exported as a `clear` box called after the obstacle that opens it, so a click on the bare wall in a break still resolves to an id. `model/cli.py` `main()`: export set and summary. The `export/c6remote-caps.json` and `export/c6remote-features.json` exports feed the viewer; never remove them. Each cap also exports a `-blank` twin at `legend=False`, which stays out of `c6remote-caps.json` because the viewer loads every entry there as a cap.
- `model/support.py` makes the board support runs from the board profile, bottom courtyards, assembly solids, the end screw block, and support parameters. `support_obstacles()` names each keepout after the board: a courtyard refdes, a through-board solid index, or `end screw block`. `ledge_breaks()` and `_ledge_blank()` are shared with the front ledges. Both the support checks and the feature export read the names.
- `model/front_ledge.py` makes the front shell's board hold-down ledges: the back ledge blank turned over, with flat undersides at `BOARD_TOP + FRONT_LEDGE_GAP`, one run set per long side, inside `FRONT_LEDGE_REACH` of the grip edge. `front_ledge_obstacles()` derives every break from the top courtyards, the assembly solids above the bearing plane, and the V2 part bodies. `front_shell()` fuses `front_ledge_runs()` into both fronts.
- `checks/support.py` probes clearance, bearing, minimum run length, print angle, and back-shell fusion on the built geometry.
- `checks/front_ledge.py` probes the built front shell: run window and length, fusion, bearing plane and flat width, clearance to courtyards and solids, material intact after the later cuts, slope angle, and fit against the pads and caps.
- `checks/legacy.py` probes the V2 top pad: the nib and kept V3 plunger bottoms and the fit in the FDM front. It probes the V2 TPU top pad's skirt depth against the V1 pad's built plunger bottoms, and its board clearance, and that each moved V2 body sits at its V2 placement. `board.legacy_frame_check()` reads the V2 outline out of `board/c6remote-v2-board-only.step`, static geometry frozen at release `2026.8.0`, commit `d0a2c2e`, and fails if V2 and V3 stop sharing a frame. `board.legacy_components()` reads V2's placements out of `board/c6remote-v2-pos.csv`, frozen at the same commit. Do not regenerate either file. V2 shell fit is not verified. Read `README.md` for the compatibility limits.
- `checks/fdm.py` probes the FDM front: the face is material at every site `checks/keypad.py` reads the recess as dished at, the groove is cut to depth all the way round with real material left under it, and the flat the built shell has out to its own top edge chamfer is `EDGE_R_FRONT_FDM`'s with `FDM_OUTLINE_EDGE_CLEAR` of it outboard of the groove. It imports `checks/keypad.py`'s own probe sites so the two passes read the same places with opposite verdicts.
- `checks/` mirrors the features, one module each, `checks/cli.py` owns the registry, solid demand-loading, and `--only`. Cross-feature checks (`interference`, `feature_clashes`) live in the `assembly` feature; a scoped run prints which features it skipped and exits nonzero on failure.

## Board support ledges

Keep the support ledges in the back shell. Use the same full-length runs to cut matching relief from the front shell. The front shell also has hold-down ledges near the grip end (`model/front_ledge.py`). They mirror the back ledges from above and reuse the same blank, break rules, and parameters. The relief stands `SUPPORT_SKIRT_FIT` above the ledge tops, so the front skirt never lands on a ledge.

Keep a 0.25 mm gap below the board and a 3 mm bearing surface. Keep one straight 45 degree underside for FDM printing.

Derive all breaks from board obstacles. Remove fragments below `SUPPORT_MIN_RUN`. A through-board solid that reaches a long side wall opens a break of at least `SUPPORT_MIN_BREAK`. Do not add local end trims or separate wedges.

After a support change, run this workflow from the repository root:

```bash
case/.venv/bin/python case/check.py --only support,front_ledge,shells
case/.venv/bin/python case/check.py
../c6remote-explode/preview-case.sh --full
```

Inspect both shell STLs and the exploded view. Confirm that the front shell has no unwanted lower side geometry.

## Disciplines

- A check must probe the BUILT solid, not restate the formula that built it. This model shipped several vacuous passes before that rule; assume any new check is vacuous until proven otherwise.
- The solid is not the artifact either: STLs are, and a valid solid can still mesh to a torn surface. `parts_are_sound` in `checks/shells.py` is the only pass that reads a mesh, and it exists because a keypad recess once lofted to something BRepCheck called valid whose STL was ripped open across the whole front face, with every other pass green. After any change to a lofted or swept surface, look at the exported STL, not just the check output.
- Geometry stays on build123d's public API. No `import OCP`, no `.wrapped`: build123d already covers booleans, `.volume`, STEP/BREP IO, and STL tessellation (`export_stl`). If an operation is genuinely mesh-native (mesh boolean, point sampling, repair), `trimesh` is installed in the venv; declare it in `requirements.txt` on first real use. Raw OCP through `.wrapped` is the last resort, confined to one small helper with a comment saying what build123d lacks.
- Perturb-test every new check: break the param, watch it fail with a sensible message, restore.
- Refactors gate on byte-identical exports (md5 over `case/export/`) and identical check output. STL export is deterministic enough to gate on, except one known flake in the back shell tessellation that the STL cache absorbs.
- A green scoped run is not a green full run; the skip line exists so nobody mistakes one.
- `SWITCH_HEIGHT` and `SWITCH_TRAVEL` are hand-entered, unmeasured; measure a real TL3315 before printing.
